Key Concepts
How Every Stage Works
📄
Document Ingestion
Raw documents are loaded, cleaned and stripped of noise. Metadata like source, page and date is preserved alongside the text for later attribution.
⚡ Garbage in, garbage out — preprocessing quality determines answer quality.
✂
Text Chunking
Documents are split into overlapping passages of 200–500 tokens. Chunk size and stride are critical hyperparameters: too small loses context; too large dilutes relevance.
⚡ Overlapping windows (10-20% stride) prevent key facts splitting across boundaries.
🔢
Embedding Generation
Each chunk is transformed into a dense vector of 768–3072 numbers. Semantically similar text lands close together in this high-dimensional space — the heart of semantic search.
⚡ The embedding model is the backbone. Better embeddings = better retrieval accuracy.
🗄
Vector Store
Embeddings are indexed in a vector database (Pinecone, FAISS, Chroma). ANN algorithms like HNSW retrieve the nearest neighbors in milliseconds across millions of vectors.
⚡ ANN search is O(log n). Cosine similarity is the most common distance metric used.
🔍
Similarity Search
The query vector is compared against all stored embeddings. Top-k chunks (typically 3–5) with highest similarity scores become the context window for the LLM.
⚡ Re-ranking with a cross-encoder after ANN retrieval dramatically lifts precision.
🧠
LLM Synthesis
Retrieved chunks + query are injected into the LLM prompt. The model synthesizes a grounded answer using only provided context — no hallucination, full attribution.
⚡ Prompt: "Answer ONLY from context. If absent, say so." eliminates confabulation.
