The Problem Space

Why Traditional
Approaches Break

Six architectural pain points that every enterprise data warehouse eventually hits — and how Data Vault solves each one.

🔄
3NF + Star Schema
Schema Rigidity
New source system = ALTER TABLE cascade. Historical context is destroyed. DV adds a new satellite — zero impact to existing structures.
⏱
Star Schema
Lost Audit Trail
SCD2 tracks what changed but not when it was loaded. DV's insert-only + load_date provides full bit-temporal history natively.
🚫
3NF (Inmon)
Sequential Loading
FK constraints force dims before facts. DV hash keys are deterministic — every table loads in parallel, no dependencies.
🔗
All Approaches
Source Coupling
CRM, ERP, Billing have conflicting customer keys. Traditional models force early merging. DV isolates each source in its own satellite.
📊
ETL-first Design
Business Rule Lock-in
Business rules baked into load pipelines destroy source data. DV's Raw Vault preserves raw truth; Business Vault holds rules separately.
📈
Star Schema
Upfront Bus Matrix
Kimball requires enterprise-wide conformed dims from day one. DV is incrementally buildable — add hubs and satellites as needs arise.

Standards

Key Rules

Data Vault 2.0 is a standards-based methodology. These rules are non-negotiable.

R01
Hash Keys on All Tables
MD5/SHA-1 of business key. Deterministic. Eliminates sequence dependencies. Enables parallel loading.
R02
Insert-Only Architecture
No UPDATE or DELETE. Ever. New satellite row = new load date. Complete immutable audit trail.
R03
Load Date on Every Row
LOAD_DATE = when data arrived in the warehouse. Distinct from EFFECTIVE_DATE (business reality).
R04
Record Source Mandatory
Every row identifies its source system. Enables full data lineage and source system auditing.
R05
One Satellite Per Source
SAT_CUSTOMER_CRM and SAT_CUSTOMER_ERP coexist. Schema changes in CRM don't affect ERP.
R06
HASH_DIFF for Change Detection
Composite hash of all attributes. If HASH_DIFF matches last row → no insert needed. Efficient CDC.
R07
Hubs Hold Business Keys Only
No descriptive attributes in Hubs. Ever. Attributes in Satellites. Hubs become immutable anchors.
R08
Links Hold No Attributes
Metrics of a relationship (amounts, dates) go in Link Satellites, not the Link itself.
R09
No Business Logic in Raw Vault
Raw Vault is technical only. Business rules live in Business Vault. Enables rule versioning and reprocessing.
R10
Information Mart Is Disposable
Marts are derived from the vault and fully rebuildable. Change requirements → rebuild mart. Vault stays intact.
R11
Metadata-Driven ETL
Loads driven by configuration, not hardcoded SQL. Enables automated code generation and consistent patterns at scale.
R12
Parallel Load Pattern
No FK constraints between tables. All Hubs and Links load simultaneously. Satellites load after parent confirmed.
